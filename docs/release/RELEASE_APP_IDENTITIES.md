# macOS application identities

| Artifact | Purpose | Bundle name | Bundle identifier | Defined in | State |
| --- | --- | --- | --- | --- | --- |
| Release build | Installed, frozen Apple Silicon app | `Mucaro AI.app` | `ai.mucaro.app` | `scripts/build_macos_app.py`, `packaging/macos/mucaro.spec` | Release lane; see `docs/RELEASE_STATUS.md` for its certification state |
| Checkout setup launcher | Sets up the source checkout and opens its own window; also the wrapper generated by `mucaro package macos-app` | `Mucaro AI Setup.app` | `ai.mucaro.source-launcher` | `backend/app/packaging.py`, tracked `Mucaro AI Setup.app` | Source-bound; not a release artifact |
| Portable lane | Embedded-runtime portable bundle | `Mucaro AI Portable.app` | `ai.mucaro.portable` | `backend/app/portable_runtime.py` | Separate lane; does not stand in for the release build |

These are three distinct artifact identities. A similar user-facing purpose or icon
does not equate their runtime, signature, installation, upgrade, or release
certification. The Setup.app is bound to its checkout and must not be renamed
to the release bundle. Keep the bundle identifiers disjoint so macOS LaunchServices
and installation receipts cannot silently select the other application.

If a bundle identifier, bundle name, or distribution class changes, amend this
mapping in the same change. `backend/tests/test_release_app_identities.py` fails
when this table and the constants in the files above disagree.

This document records identities only. It makes no certification claim; release
state is recorded in `docs/RELEASE_STATUS.md` and the release ledgers.
