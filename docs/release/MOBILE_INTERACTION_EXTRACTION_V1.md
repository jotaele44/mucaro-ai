Baseline comparison and implementation order
At the inspected commit, frontend/src/App.jsx exposes a conversation list, text query, ask, rename and delete; frontend/src/api.js has ask/conversation endpoints. backend/app/main.py separately exposes tool requests, approve/deny/run and an execution planning gate. backend/app/conversations.py stores a list of turns using a SQLite JSON upsert. The inspected paths provide building blocks for F01/F02/F05/F07, but no observed evidence that the integrated pending question, queued message, resumable run, background task, tool drawer or PR artifact flow exists. backend/app/response_flow.py and docs/RESPONSE_FLOW.md returned 404 at this commit, so earlier response-flow proposals must not be treated as merged.
1. Freeze repo head, enumerate routes/components/tests, and define the typed response envelope: text, inert code, question, tool call/result, artifact, and task receipt. Keep answer trace distinct from UI response envelope.
2. Add transactional per-conversation writes or event ledger, optimistic versioning and request idempotency before claiming restartable runs. Persist turn IDs, interaction IDs and tool receipt IDs. Establish one pending interaction maximum.
3. Implement pending-question state machine (create → display → choose/freeform/dismiss → resolve → resume), then interruption/queue semantics. Resolve by IDs, never label text; reject stale/double choices and ambiguous labels.
4. Bind run policy and one-time permissions to exact tool calls. Render each call and aggregate attempts from the ledger. Reconcile partial success before any batch retry; truthful statuses take precedence over assistant prose.
5. Implement mobile composer, conversation transcript, sheets and drawers with one canonical home per action, then background jobs and artifact navigation. GitHub PR control is a separate connector capability, not implied by a UI mock.
6. Run positive and negative regression gates: normal choice, Other, new-topic dismissal, interrupted/reopened question, stale/duplicate submission, concurrent requests, denied call, retry of only failed action, queue ordering, render-only inert code, mobile keyboard/scroll, reload and exact PR identity. Verify desktop and iPhone widths with rendered QA. Freeze commit, output and test receipts only after these pass.
